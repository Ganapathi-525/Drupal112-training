19. Interview Q&A

Answer in your own words. The short answers below are interview-length.

A. Basics

1. What is Drupal?

An open-source PHP content management framework on Symfony, used for complex, scalable, secure sites with granular permissions and multilingual support.

2. What is the difference between a node, a content type and a field?

A node is one piece of content. A content type is the template/bundle defining its fields. A field is a data slot.

3. What is an entity? A bundle?

An entity is a data object managed by the Entity API (node, user, term, media...). A bundle is a subtype of an entity type (Article is a bundle of node).

4. What is the difference between content and configuration?

Configuration is site structure/settings exportable as YAML (content types, views, roles). Content is user data (nodes, users, terms) kept in the database, moved by migrations or DB copy.

5. What is the difference between core, contrib and custom?

Core ships with Drupal; contrib is community code on drupal.org; custom is code written for your project.

6. What is a block? A region?

A block is a placeable chunk of output. A region is a theme area where blocks go.

7. What is a view mode?

A named display configuration of an entity (Full, Teaser, Card) so the same content renders differently.

8. What is the difference between a widget and a formatter?

Widget = input on the edit form. Formatter = output on display.

9. What is a taxonomy?

A system of vocabularies containing terms used to categorise content.

10. What is Drupal CMS?

A pre-configured product built on Drupal core using recipes, aimed at easy site building; underneath it is the same Drupal.

11. What is Drupal Core's scaffold and recommended-project?

drupal/recommended-project is the Composer template for new sites; drupal/core-composer-scaffold copies files like index.php into the docroot; drupal/core-recommended locks dependency versions.

12. What is the difference between Drupal 10 and 11?

Drupal 11 requires newer PHP (8.3+), updated Symfony 7, removes deprecated APIs, adds OOP hooks, attributes for plugins, Navigation, recipes and SDC maturing, and Single Directory Components.

13. What is a distribution, install profile, recipe?

Profile: initial setup at install. Distribution: profile plus code for a use case. Recipe: a one-time applicable package of config/modules/content.

14. What does settings.php contain?

Database credentials, hash salt, config sync directory, trusted hosts, file paths, overrides. Environment-specific; not committed with secrets.

15. What is the front controller?

web/index.php, the single entry point that boots Drupal.

B. Site building

16. How do you create a content type and add a field?

Structure → Content types → Add; Manage fields → Add field; configure widget (form display) and formatter (display).

17. How do you show the same content differently in two places?

Create/enable view modes and configure Manage display for each; select the mode in the view or template.

18. What is Views?

A UI query builder for lists, built on displays, fields, filters, sorts, relationships and contextual filters.

19. Contextual filter vs exposed filter?

Contextual filter takes its value from the URL/context. Exposed filter is a form control shown to the visitor.

20. What is a relationship in Views?

A join to a related entity so you can show its fields or filter by them.

21. How do you avoid duplicate rows in a View?

Enable Distinct, use aggregation, or adjust the multi-value field's "Display all values in the same row".

22. How do you add a view to a menu?

Page display → Page settings → Menu → Normal menu entry.

23. How do you display a View in a block?

Add a Block display, then place it in Structure → Block layout.

24. What is the difference between Layout Builder and Paragraphs?

Layout Builder arranges fields/blocks in layouts visually (per content type or per node). Paragraphs lets editors compose content from reusable component types inside a field.

25. Why use Media instead of an Image field?

Media entities are reusable, have metadata (alt, caption), a library UI, and support many sources (video, remote video, documents).

26. How do text formats protect a site?

They run filters (HTML restriction) on user input; weak formats allow XSS, so only trusted roles get Full HTML.

27. How do you create and use roles?

People → Roles; assign permissions on the Permissions page; assign roles to users.

28. What can user 1 do?

Bypasses all permission checks. Use sparingly; use an administrator role for daily work.

29. How do you set up URL aliases?

Manually per node or automatically with Pathauto patterns.

30. How do you enable moderation workflows?

Enable Workflows and Content Moderation; create/edit the Editorial workflow; attach content types; give roles transition permissions.

31. How do you build a contact form?

Core Contact module (/contact) for simple needs or Webform for advanced forms.

32. What are image styles?

Reusable image transformations (scale, crop, convert) that create derivative images on demand.

33. How does Drupal handle multilingual?

Language, Content Translation, Interface Translation and Configuration Translation modules provide languages, translatable fields, translated UI strings and translated config.

34. How do you make a field translatable?

Configuration → Content language and translation → enable for the entity bundle and tick the field.

35. What is a revision?

A stored historical version of an entity; you can compare and revert.

C. Config, deployment, tooling

36. How does configuration management work?

Active config lives in the database; drush cex writes YAML to the sync directory under Git, and drush cim imports it on other environments.

37. What is the deployment order?

composer install → drush updb → drush cim → drush cr (or drush deploy).

38. What is Config Split?

Contrib module that creates environment-specific config sets (dev modules, debug settings).

39. Why does config import complain about UUID?

The site UUID differs; sites must share one UUID to import each other's config.

40. composer.json vs composer.lock?

json = requirements; lock = exact installed versions. Servers use composer install to reproduce.

41. How do you update Drupal core?

Backup; composer update "drupal/core-*" --with-all-dependencies; drush updb; drush cr; test; commit.

42. How do you apply a patch to a contrib module?

Use cweagans/composer-patches, add the patch URL in extra.patches of composer.json, run composer update drupal/module.

43. What is Drush? What is Composer? Difference?

Composer manages PHP packages (installs code). Drush operates on a Drupal site (cache, config, updates).

44. What is DDEV?

A Docker-based local development environment with web server, PHP, database, and tools.

45. How do you migrate a database between environments?

drush sql:dump and drush sql:cli < file, or ddev export-db/import-db, or drush sql:sync @source @self with aliases.

46. What is a Drush alias?

A named remote site definition (@prod) in drush/sites/*.site.yml for running commands remotely.

47. What is the difference between drush cr and drush cc all?

cr rebuilds the registry/container and clears all caches (the right one in modern Drupal); cc all is legacy.

48. How do you do a major upgrade 10 → 11?

Update to the latest 10.x, enable Upgrade Status, fix deprecated code and incompatible modules, update PHP, then require core 11 with Composer, run updb, test.

49. Which files should and should not be in Git?

In: custom code, config, composer files. Out: vendor/, core/contrib (usually), files directory, local settings, secrets.

50. How do you manage secrets?

Environment variables, settings.local.php not in Git, Key module, hosting secret managers.

D. Theming

51. What template engine does Drupal use?

Twig (Symfony); auto-escapes output.

52. How do you override a template?

Enable Twig debug, find the file name suggestion, copy the core template into the theme's templates/, rename for specificity, clear cache.

53. What is a preprocess function?

THEME_preprocess_HOOK(&$variables) that prepares variables for a template.

54. How do you add CSS/JS?

Define a library in THEME.libraries.yml, attach it via info.yml, Twig attach_library(), or #attached.

55. Base theme vs sub-theme vs Starterkit?

Sub-theme inherits from a base theme; Starterkit generates an independent copy.

56. What is SDC?

Single Directory Components: Twig + CSS + JS + metadata schema in one folder, reusable and documented.

57. What are template suggestions?

Alternative file names Drupal tries, from most specific to least, for a render element.

58. What does {{ content|without('field_x') }} do?

Renders remaining content without that field.

59. Why is |raw dangerous?

It disables escaping and enables XSS if the value contains user input.

60. How do you debug Twig?

Set twig.config.debug: true in services.yml, use {{ dump(var) }} or kint, inspect HTML comments.

61. What is the Olivero theme? Claro? Stable9? Starterkit?

Olivero = default front end; Claro = admin; Stable9 = stable markup base; Starterkit = theme generator.

62. What is a render array?

A nested PHP array describing output with # properties (#theme, #type, #markup, #cache, #attached), rendered by the render system.

63. How do you make a theme responsive?

Mobile-first CSS, breakpoints file, responsive image styles, viewport meta (in base templates).

E. Module development

64. What files make a minimum module?

Only MODULE.info.yml, in web/modules/custom/MODULE/.

65. How do you create a custom page?

Routing YAML entry + controller returning a render array.

66. How do you restrict access to a route?

Requirements: _permission, _role, _entity_access, _custom_access.

67. What is a service?

A reusable object defined in services.yml and created by the container.

68. What is dependency injection and why use it?

Passing dependencies via the constructor for testability and loose coupling; avoid \Drupal::service() inside classes.

69. Hooks vs events?

Hooks are named Drupal extension points (OOP attribute #[Hook] in D11); events use Symfony's dispatcher with subscriber classes and priorities.

70. What is a plugin?

A discoverable class implementing one variant of a feature, e.g. blocks, field formatters, queue workers.

71. Annotation vs attribute plugin discovery?

Both identify plugins; attributes (#[Block]) are native PHP 8 and preferred in Drupal 11; annotations still work.

72. How do you create a block programmatically?

A class in src/Plugin/Block extending BlockBase with #[Block] and build().

73. How do you create a form?

Class extending FormBase/ConfigFormBase implementing getFormId, buildForm, validateForm, submitForm, with a route using _form.

74. How do you alter a form?

hook_form_alter or hook_form_FORM_ID_alter.

75. How do you load/save an entity?

Node::load(), Node::create(), $node->save() or the entity type manager storage.

76. Why does entityQuery need accessCheck()?

It must be explicit whether to enforce entity access; omitted causes an exception since Drupal 10.

77. How do you write a database query safely?

Database API with placeholders/conditions, never string concatenation.

78. How do you store module settings?

Config API with defaults in config/install and a schema, edited with a ConfigFormBase form.

79. State vs config vs settings?

Config = exportable site config; state = environment-specific runtime values; settings = server config in settings.php.

80. What is hook_update_N?

One-time database/config update run by drush updb when deploying new code.

81. How do you create a custom entity?

Define the entity class with #[ContentEntityType], interface, base fields, handlers and routes (use drush generate entity:content), then install it via update hook or module install.

82. What is a queue worker used for?

Deferring heavy or slow tasks (emails, API calls) processed by cron or drush queue:run.

83. How do you add a custom field widget or formatter?

Plugin classes in src/Plugin/Field/FieldWidget and FieldFormatter.

84. How do you create a custom Views field/filter?

Plugin classes under src/Plugin/views/field etc. plus hook_views_data for custom tables.

85. How do you log errors?

\Drupal::logger('mod')->error(...) or an injected logger factory.

86. What is a route parameter converter / upcasting?

Converting {node} in a path into a loaded Node object automatically.

87. How do you handle AJAX in forms?

Add #ajax with a callback and wrapper to an element; Drupal replaces the wrapper with the callback's render array.

88. How do you send an email?

Mail manager service + hook_mail().

89. How do you run code on cron?

hook_cron() or a QueueWorker with a cron time.

90. How do you redirect a user after login?

Use the user_login_form alter with a submit handler ($form_state->setRedirect), an event subscriber, or the Login Destination module.

F. Caching, performance, security

91. Explain cache tags, contexts and max-age.

Tags invalidate caches when data changes; contexts create variations by request conditions; max-age limits lifetime.

92. What is BigPipe? Dynamic page cache?

BigPipe streams personalised pieces after cached content; dynamic page cache caches pages for authenticated users with placeholders for dynamic parts.

93. What does max-age 0 do?

Makes the response uncacheable; it bubbles up and can disable page caching, so avoid it.

94. How do you speed up a slow Drupal site?

Enable caches and aggregation, Redis, CDN/Varnish, optimise Views and images, use proper cache metadata, profile with Blackfire/Xdebug, upgrade PHP, add DB indexes, reduce modules.

95. How do you prevent XSS?

Rely on Twig auto-escape, placeholders in t(), restricted text formats, Xss::filter, avoid |raw.

96. How do you prevent SQL injection?

Query builder and placeholders.

97. How do you protect against CSRF?

Form tokens; _csrf_token route requirement for state-changing links.

98. How do you keep a Drupal site secure?

Update promptly, least privilege, HTTPS, trusted hosts, restricted formats, no debug in prod, private files, backups, monitor advisories.

99. What are Drupal security advisories?

SA-CORE-YYYY-NNN and SA-CONTRIB-YYYY-NNN published by the Drupal Security Team with severity and fix versions.

100. What is the flood control?

Core limits repeated login attempts per user/IP and exposes a Flood API for custom features.

G. Scenario questions

101. "A page shows stale content after an edit." What do you check?

Cache tags on the render array, view cache settings, CDN/Varnish purge, custom code with max-age; not just drush cr.

102. "After deployment the site shows config errors."

Check order (updb before cim), UUID mismatch, missing modules in code, drush config:status, logs.

103. "Editors need to approve content before publishing."

Content Moderation + Workflows with an Editorial workflow and role-based transitions.

104. "Show related articles by shared tags."

View with contextual filter "Has taxonomy term ID" using the current node's terms (default value: PHP-free option via Views "Taxonomy terms on node" with "Allow multiple values") and exclude the current node via another contextual filter "Content ID" with "Exclude".

105. "Build a content listing with search, filters and pagination."

Views with exposed filters + pager, or Search API with Facets for large datasets.

106. "Import 10,000 rows from CSV."

Migrate API with migrate_plus, migrate_source_csv, run with drush migrate:import, rollback to retry.

107. "Expose content to a React app."

JSON:API with filters/includes, CORS, Simple OAuth for authentication, caching with tags.

108. "A module update breaks the site."

Restore the backup/snapshot, check release notes and change records, update in a branch, run tests, fix deprecations, or apply a patch.

109. "Restrict a page to premium members."

Add a role and route/permission, or use Group/Content Access; for node-level, node grants.

110. "Different layout for one landing page."

Layout Builder per-node override, or a template suggestion by node ID/alias.

20.3 Interview day self-check, with model answers

Cover the answer, say yours out loud, then compare. Aim for 30-60 seconds each.

Q1. Explain entity, bundle and field.

An entity type is a kind of data object, such as node, user, taxonomy term or media. A bundle is a subtype of that entity type: Article and Event are bundles of node, and each bundle can have different fields. A field is a typed piece of data attached to a bundle, such as a date, text or reference. Example: "Event" is a node bundle, and its field_location holds the venue.

Q2. Config vs content: what is the difference and how do you move each?

Config is site structure and settings (content types, fields, views, roles, blocks). It is stored in the database but exported to YAML with drush cex and imported with drush cim, so it travels through Git. Content is user data (nodes, users, terms, media). It is not in config export. You move it with a database copy, the Migrate API, or a default-content approach. Rule of thumb: config goes up (dev to prod through Git), content comes down (prod to dev through a database copy).

Q3. Walk me through what happens when a page is requested.

The web server sends the request to web/index.php. Drupal boots the Symfony kernel and the service container. The router matches the path to a route (from a routing.yml file or a View). Access checks run. A controller (or View or entity handler) returns a render array. The render system turns it into HTML using Twig templates and the theme, attaching cache metadata. The response goes back to the browser. For anonymous users the Internal Page Cache can serve the whole page early, and for logged-in users the Dynamic Page Cache serves most of it.

Q4. Explain cache tags, contexts and max-age.

Tags say what data the output depends on (node:5, node_list). When that data changes, Drupal invalidates every cache item carrying the tag. Contexts say what request conditions make the output vary (user.roles, languages, url.query_args), so one cached copy is stored per value. Max-age says how long the output may be cached (Cache::PERMANENT by default, 0 means never cache and should be avoided). Example: a "latest events" block should carry the tag node_list:event, so it refreshes when any Event is saved, with no manual cache clear.

Q5. What is dependency injection and why does Drupal use it?

Dependency injection means a class receives the objects it needs (database, current user, logger) through its constructor instead of creating them or calling \Drupal::service() inside. Drupal uses it so classes are testable (you pass mocks), loosely coupled, and free of hidden global state. Controllers, forms and plugins get their dependencies through a static create() factory that reads from the service container.

Q6. Hooks vs events vs plugins: when do you use each?

Hooks are Drupal-specific extension points where you alter or react to something Drupal already does (alter a form, react to a node save). In Drupal 11 you write them as class methods with the #[Hook] attribute. Events are Symfony's dispatcher: subscriber classes with priorities, used for request/response lifecycle and newer subsystems. Plugins are for adding a new implementation of a feature that Drupal discovers automatically (a block, field formatter, queue worker). Short version: alter existing behavior with a hook or event, add a new option with a plugin.

Q7. How do you create a content type, a View and a role from memory?

Content type: Structure → Content types → Add content type, then Manage fields to add fields, Manage form display for widgets, Manage display for formatters. View: Structure → Views → Add view, choose what to show and the page or block option, then add fields, filters and sorts and Save. Role: People → Roles → Add role, then People → Permissions to tick permissions, then assign the role on the user edit form. Command-line role: drush role:create editor "Editor" and drush role:perm:add editor "permission name".

Q8. How do you export config, write a route + controller, a block, and override a template?

Export config: drush cex -y. Route + controller: add an entry in MODULE.routing.yml with path, defaults: _controller and requirements: _permission, then a controller class in src/Controller returning a render array, then drush cr. Block: a class in src/Plugin/Block extending BlockBase, with the #[Block(id:, admin_label:)] attribute and a build() method, then place it in Block layout. Override a template: turn on Twig debug, read the file-name suggestions in the page source, copy the core template into your theme's templates/, rename it for the specific case (such as node--event--teaser.html.twig), edit, and run drush cr.

Q9. What is the update and deploy order, and which commands do you use?

Back up first. Then get the code (git pull), composer install (use --no-dev on production), drush updb -y, drush cim -y, drush cr. drush deploy runs the update, import and cache steps in the right order. The order matters because database updates must run before config import, and caches are cleared last. Everyday commands: ddev start, ddev composer require drupal/NAME, ddev drush en NAME, drush cr, drush uli, drush ws (logs).

Q10. What do you say when you don't know the answer?

Be honest and show your method: "I haven't used that directly. I would start with api.drupal.org for the API, the module's drupal.org page and issue queue, and the change records for my Drupal version. Then I would test it on a local DDEV site before touching anything shared." Interviewers value a clear way of finding out far more than a guess that turns out wrong.

Q11. Do I have 3 real stories? (templates, fill in with your own facts)

Story 1, a problem you solved: "On my training Events site, the Latest Events block did not show new events. I checked the block's #cache and found a fixed max-age with no cache tag. I added the node_list:event tag, and new events appeared immediately after saving."

Story 2, something you built: "I built an Events site with an Event content type, a View with an exposed category filter, a custom theme template for the teaser, and a custom module with a controller, a block and a feedback form. I exported config with drush cex and kept it in Git."

Story 3, a mistake you learned from: "I edited a module's config only in the UI on one environment and lost it on the next deploy because I had not exported it. Now I always run drush cex, commit the YAML, and deploy with drush cim."

Important: these are templates. Only tell a story that is true for you. The examples above match the exercises in this guide, so they are true once you have actually done those exercises.

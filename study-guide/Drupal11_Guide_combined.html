1. Drupal basics and architecture

1.1 What is Drupal?

Definition: Drupal is a free, open-source content management framework (CMF) written in PHP, built on Symfony components, using a database (MySQL/MariaDB/PostgreSQL/SQLite), and managed with Composer.

Interview one-liner: "Drupal is an open-source, API-first content management framework on PHP and Symfony. It is strongest for complex content models, multilingual sites, granular permissions and large enterprise or government sites."

1.2 CMS vs CMF vs framework

TermMeaning

CMFContent management framework: a CMS whose pieces you can extend and reuse as a framework. Drupal fits here.
FrameworkCode library for building apps (Symfony, Laravel). Drupal uses Symfony underneath.

1.5 How a Drupal request works (explain this in interviews)

  1. The browser requests /events; the web server sends it to web/index.php.
  2. Drupal boots the kernel (Symfony HttpKernel) and the service container.
  3. Routing matches the path to a route (from a *.routing.yml file or a View).
  4. Access checks decide whether the user may view it.
  5. A controller (or View, or Entity handler) returns a render array.
  6. The render system converts it to HTML using Twig templates and the theme, applying cache metadata.
  7. A Response is returned to the browser.

1.7 Release cycle (interview favourite)

  • Drupal uses semantic versioning: 11.x. A new minor version (11.1, 11.2...) comes about every six months; patch releases fix bugs and security.
  • Major versions (10, 11, 12) remove deprecated code. Move from 10 to 11 by updating to the latest 10.x, fixing deprecations (tool: Upgrade Status module, drupal-check, Rector) and then running composer require drupal/core-recommended:^11 ....
  • Drupal CMS is a product built on Drupal core with recipes and a friendly editor experience. It is not a different codebase.

4. Content types, fields, view modes

4.1 Meaning

Content type = a bundle of the node entity type with its own fields and settings. Field = typed data attached to an entity bundle. A field has a storage (type, cardinality: shared across bundles) and an instance/config (label, required, per bundle).

Interview one-liner: "A content type defines the structure of a kind of content. Fields hold the data, widgets control the edit form, formatters control the output, and view modes let the same content render differently in teasers, cards or full pages."

4.2 Core field types

Field typeUse for
Text (plain / formatted / long / with summary)Titles, descriptions, body
Number (integer, decimal, float)Price, quantity
BooleanYes/no flags (Featured)
Date / Date range / TimestampEvent dates
List (text, integer, float)Fixed options (select, radios, checkboxes)
LinkURL with title
Email, TelephoneContact info

Image / FileDirect uploads (media is preferred for reuse)

4.3 How to create a content type (navigation)

  1. Structure → Content types → Add content type (/admin/structure/types/add).
  2. Name: Event. Description. In Publishing options: default published, create new revision. In Display settings: toggle "Display author and date information". In Menu settings: allowed menus. Save.
  3. Click Manage fields → Create a new field → choose type → set label & machine name (field_event_date) → set storage settings (cannot change type later) → field settings (required, help text, default) → Save.
  4. Manage form display: drag fields to reorder; choose widget (Date picker, Autocomplete, Select list, Check boxes/radios, Media library).
  5. Manage display: choose formatter, label position (above, inline, hidden), and which fields appear in Default, Teaser, other view modes. Use "Custom display settings" at the bottom to enable more view modes for that bundle.
Gotcha: The field machine name and type are permanent. Plan names before saving. Deleting a field deletes its data.

4.4 Entity reference settings

  • Reference type: what is referenced (Content, Taxonomy term, User, Media).
  • Reference method: Default (choose bundles, sort) or View (use a Views display to filter choices).
  • Create referenced entities if they don't already exist: lets editors add new terms on the fly with autocomplete (tags).
  • Allowed number of values: Limited (1, 2...), or Unlimited.

4.5 View modes and form modes

  • View mode: output variant (full, teaser, search result, card). Create new ones at Structure → Display modes → View modes (/admin/structure/display-modes/view).
  • Form mode: edit form variant. Structure → Display modes → Form modes.

Use a view mode when you need the same content shown differently in different places (a list card vs a full page). In a View, choose "Show: Content" with a view mode, or "Fields".

4.6 Revisions, moderation, status

  • Revisions: every save can create a new version (the "Revisions" tab on a node). You can revert.
  • Content Moderation (core module) and Workflows (core): draft → review → published states. Enable both modules, then go to Configuration → Workflow → Workflows (/admin/config/workflow/workflows), edit "Editorial", and attach it to the Event content type.
  • Published flag: unpublished nodes are visible only to users with the right permission.

4.7 URL aliases

  • Every node has a system path /node/5. An alias like /events/my-concert is nicer.
  • Manual: node edit form → URL alias panel. Automatic: Pathauto module, pattern /events/[node:title] at /admin/config/search/path/patterns.

5. Views

5.1 Meaning

Views is a query builder with a UI (in core). It builds a SQL query against entities, applies filters and sorts, and renders the result as a page, block, feed, or other display.

Interview one-liner: "Views lets site builders create lists and reports without writing SQL or PHP. You choose the base table, fields, filters, sorts, relationships and a display such as a page or block."

5.2 Views vocabulary

TermMeaning
ViewThe saved configuration (a config entity).
DisplayAn output of the view: Page, Block, Feed, Attachment, Embed, REST export, Entity reference.
FormatThe layout: Unformatted list, Table, Grid, HTML list, Responsive grid, Serializer.
Row styleWhether rows show Fields or rendered Content (entity in a view mode).
FieldsColumns of data.
Filter criteriaConditions applied to the query (fixed or exposed to visitors).
Exposed filterA filter shown as a form to the visitor.
Sort criteriaORDER BY, can also be exposed.
RelationshipA JOIN to a related entity so you can use its fields (example: content → author).
Contextual filterA filter whose value comes from the URL or context (argument). Example: /events/music.
PagerPagination (full, mini, "display a specified number", "display all").
Header / Footer / EmptyText or areas above, below, and when there are no results.
AggregationGROUP BY with COUNT, SUM, etc.
Rewrite resultsChange a field's output using tokens like {{ title }}.
OverrideSetting applies to one display only, not "All displays".

5.3 Create a view (navigation)

  1. Structure → Views → Add view (/admin/structure/views/add).
  2. View name; Show: Content of type Event sorted by Newest first.
  3. Tick Create a page: title, path events, display format (Table or Grid of fields), items per page.
  4. Tick Create a block (optional): items 3.
  5. Save and edit.

The editing screen

  • Top: displays list. Left column: Title, Format, Fields, Filter, Sort. Right: Advanced (contextual filters, relationships, exposed form, query settings, caching, header, footer, no results).
  • Click Add next to Fields / Filter criteria / Sort criteria, search by name, tick it, Add and configure.
  • The dropdown For: All displays / This page (override) decides scope. Choose carefully.
  • Bottom Preview, with "Auto preview" ticked, shows results as you edit.
  • Always click Save.

5.4 Exposed filter example (Category)

  1. Filter criteria → Add → "Event: Category (field_category)" → Add and configure.
  2. Tick Expose this filter to visitors. Set "Filter type to expose": Dropdown. Label: Category. Tick "Limit list to selected items" optional.
  3. Apply. Exposed form settings: Advanced → Exposed form → Exposed form style "Basic", change "Submit button text" to "Search".

5.5 Contextual filter example (category in URL)

  1. Advanced → Contextual filters → Add → "Content: Has taxonomy term ID".
  2. "When the filter value is NOT in the URL": Display all results / Hide view / Provide default value.
  3. "When the filter value IS in the URL": validation criteria "Taxonomy term" so a bad ID shows "page not found".
  4. Page path: events/%. Visiting /events/3 filters by term 3.

5.6 Relationship example

Show event author name: Advanced → Relationships → Add → "Content author" → then add field "User: Name", choosing the relationship "author". Without a relationship, you can only use fields of the base entity.

5.7 Useful Views settings

  • Query settings → Disable SQL rewriting: use rarely; it bypasses node access (security risk).
  • Caching: Tag based (default); Time based for heavy views.
  • Access: Permission or Role. Always set it on pages.
  • Use AJAX: updates the list without reloading the page.
  • Show SQL query: enable at /admin/structure/views/settings for debugging.
  • Distinct: removes duplicates (caused by multi-value fields in joins).
  • Machine name / Path / Menu: A page display can add itself to a menu (Menu: Normal menu entry).
  • Contextual links and Field rewriting let you control markup.

5.8 Common Views mistakes (interview-worthy)

  • Editing "All displays" when you meant only one display.
  • Duplicate rows (multi-value fields, relationships) → fix with Distinct or aggregation.
  • Forgetting Published = Yes filter, which shows unpublished content to editors in a public list.
  • Forgetting that views cache: after a change that doesn't appear, check caching and clear caches.

6. Taxonomy, menus, blocks, media

6.1 Taxonomy

Meaning: a classification system. A vocabulary contains terms. Terms can be hierarchical.

  • Create: Structure → Taxonomy → Add vocabulary → Add terms.
  • Hierarchy: List terms tab → drag a term under another.
  • Use: add a Reference → Taxonomy term field to a content type (widgets: autocomplete (tags style), select, check boxes/radios).
  • Term pages at /taxonomy/term/ID come from the core view "Taxonomy term".
  • Tags vs categories: tags are free-form (autocomplete with create-on-the-fly); categories are a controlled list.

6.2 Menus

  • Core menus: Main navigation, Footer, Administration, Tools, User account.
  • Add a link: Structure → Menus → Main navigation → Add link: Title, Link (/events or start typing a title), Enabled, Show as expanded, Parent, Weight.
  • From a node: Node edit form → Menu settings → Provide a menu link.
  • Display: a menu is only visible after its block is placed (6.3).
  • Menu links can be defined in code with *.links.menu.yml.

6.3 Blocks and regions

  • Place a block: Structure → Block layout → choose the theme tab → Place block next to a region → pick block → configure title, Visibility (pages, content types, roles, languages) → Save → Save blocks.
  • Custom block (block content): Content → Blocks → Add content block (e.g. "Basic block" with Body). Reusable blocks can be placed multiple times. Non-reusable ones belong to a single place (Layout Builder).
  • Block types: Structure → Block content types, to add fields to custom blocks.
  • Views blocks appear in the block list as "Views: <view name>".
  • Layout Builder (core): per-content-type or per-node drag-and-drop layouts. Enable layout_builder and layout_discovery. Then Manage display → tick "Use Layout Builder".

6.4 Media

  • Enable Media and Media Library modules (default in Standard profile).
  • Media types: Structure → Media types (Image, Document, Audio, Video, Remote video). Each is a bundle with source field and extra fields (alt, caption).
  • Add media: Content → Media → Add media.
  • Use: Add a "Media" reference field; widget "Media library".
  • Image styles: Configuration → Media → Image styles. Define scale/crop/convert (e.g. 400x300 WebP) and select it in the formatter. Responsive image styles give srcset.

6.5 Text formats and CKEditor 5

  • Configuration → Content authoring → Text formats and editors.
  • Basic HTML, Restricted HTML (no editor, anonymous users), Full HTML (trusted roles only).
  • Each format has an editor toolbar and an allowed-HTML filter. A security rule: never give anonymous users Full HTML.

7. Users, roles, permissions

7.1 Meaning

  • User = an account (an entity). User 1 (uid 1) bypasses all access checks.
  • Role = a set of permissions. Built-in: Anonymous, Authenticated (every logged-in user inherits it), and Administrator.
  • Permission = a single allowed action, provided by modules (e.g. "Event: Create new content").
Interview one-liner: "Permissions are granted to roles, and roles are assigned to users, never permissions directly to users. Anonymous and Authenticated are separate built-in roles: a logged-in user does not inherit the Anonymous role's permissions, only Authenticated plus any extra roles assigned."

7.2 Navigation

  • Add role: People → Roles → Add role (/admin/people/roles/add).
  • Permissions grid: People → Permissions (/admin/people/permissions) or per role (/admin/people/permissions/ROLE).
  • Add user: People → Add user. Assign roles on the form.
  • Registration settings: Configuration → People → Account settings. Choose "Administrators only", "Visitors", or "Visitors, but administrator approval is required".

8.3 Configuration management (CMI)

Meaning: A system that stores site configuration in the database but allows export/import as YAML files so changes move from development → staging → production under version control.

Setup

In web/sites/default/settings.php:

$settings['config_sync_directory'] = '../config/sync';

Workflow

ddev drush cex -y      # export DB config to config/sync/*.yml
git add config/ && git commit -m "Add Event content type"
# on another environment
git pull && ddev composer install
ddev drush updb -y
ddev drush cim -y      # import YAML into DB
ddev drush cr
ddev drush config:status   # show differences

Related commands

CommandUse
drush config:get system.siteRead one config object
drush config:set system.site name "My Site" -yChange one value

Key facts for interviews

  • Config files live in config/sync; the site UUID must match between environments or import fails. Set once: drush config:set system.site uuid XXXX (only for a fresh site cloned from the same codebase).
  • Config Split (contrib) keeps environment-specific config (dev modules like devel, stage_file_proxy) separate.
  • Config Ignore (contrib) excludes config you do not want overwritten.
  • Config overrides in settings.php via $config['system.site']['name'] = 'X'; never appear in the UI or export.
  • Active config = in DB; sync directory = YAML files. Config is not content, so nodes, users, terms are not exported.
  • Default config in modules sits in config/install (imported on module install) and config/optional (imported if dependencies exist). config/schema/*.schema.yml describes the structure of config.

8.4 Recipes (new in Drupal 10.3+, standard in 11)

Meaning: A recipe is a reusable, composable package that applies config, installs modules, and can add content. It is applied once; it is not an ongoing dependency like a module.

A recipe has recipe.yml with name, type, recipes:, install:, and config: sections (config: import: and actions:). Recipes live in the recipes/ folder you already have.

Recipe vs install profile vs module: a profile is chosen once at install and lives for the site's lifetime; a module is ongoing code; a recipe runs once to configure the site.

12.1 Services and the container

Service = a PHP object with one job (logger, mailer, database, current user, entity type manager). The service container creates them lazily and shares one instance. Services are declared in MODULE.services.yml.

# training.services.yml
services:
  training.greeter:
    class: Drupal\training\Greeter
    arguments: ['@current_user', '@logger.factory', '@entity_type.manager']
namespace Drupal\training;

use Drupal\Core\Session\AccountProxyInterface;
use Drupal\Core\Logger\LoggerChannelFactoryInterface;

class Greeter {
  public function __construct(
    protected AccountProxyInterface $currentUser,
    protected LoggerChannelFactoryInterface $loggerFactory,

  public function greet(): string {
    $this->loggerFactory->get('training')->info('Greeted @u', ['@u' => $this->currentUser->getDisplayName()]);
    return 'Hello ' . $this->currentUser->getDisplayName();
  }
}

12.2 Dependency injection in controllers, forms, blocks

use Symfony\Component\DependencyInjection\ContainerInterface;
class HelloController extends ControllerBase {

13.1 Entity API

Entity types: content entities (node, user, taxonomy_term, media, file, comment, block_content, paragraph) are fieldable and stored in tables; config entities (view, node_type, field_config, role, image_style) are stored in config.

use Drupal\node\Entity\Node;

// create
$node = Node::create([
  'type' => 'event',
  'title' => 'Drupal Meetup',
  'field_location' => 'Hyderabad',
  'status' => 1,
]);
$node->save();

// load
$node = Node::load(5);
$nodes = \Drupal::entityTypeManager()->getStorage('node')->loadMultiple([1, 2]);

// read/write fields
$title = $node->label();
$loc = $node->get('field_location')->value;
$node->set('field_location', 'Pune')->save();

$node->delete();

$ids = \Drupal::entityQuery('node')

Always call accessCheck(TRUE|FALSE) on entity queries (required since Drupal 10). Use TRUE for user-facing output.

Entity concepts for interviews

  • Entity type (definition class with handlers: storage, view builder, access, list builder, forms, route provider); bundle; fields: base fields (code-defined, e.g. title) vs configurable fields (UI-defined).
  • Revisions and translations are built into content entities.
  • Custom entity: define with the #[ContentEntityType] attribute, an interface, schema via base field definitions, and handlers. Scaffold with drush generate entity:content. Update schema changes with hook_update_N and EntityDefinitionUpdateManager.
  • Entity access: $entity->access('update', $account).
  • Typed data / field items: $node->field_x is a FieldItemList of FieldItems.

14.2 Security checklist

  • Use HTTPS; set $settings['trusted_host_patterns'] in settings.php.
  • Keep core and contrib updated: composer audit, Available updates report.
  • Least-privilege roles; do not hand out "administer ..." permissions.
  • Use "Basic HTML" for authenticated users, "Restricted HTML" for anonymous; Full HTML for admins only.
  • Protect settings.php: chmod 444; put sites/default/files/private outside the web root: $settings['file_private_path'] = '../private';.
  • Disable dev modules (devel, webprofiler) in production.
  • Change user 1's name from "admin"; use strong passwords; consider 2FA.
  • Block users from PHP execution in files directories (Apache/Nginx rules; Drupal writes .htaccess).
  • Check /admin/reports/status for warnings, and use the Security Review module.
  • Do not run update.php access publicly ($settings['update_free_access'] = FALSE;).

15.2 Cache metadata (the 3 pieces) — very common question

MetadataMeaningExample
Tags"What data did this depend on?" When tagged data changes, the cache is invalidated.node:5, node_list, config:system.site, user:3
Contexts"What request conditions cause variations?" One cached copy per context value.user.roles, languages, url.path, url.query_args, route, theme, user.permissions

$build['#cache'] = [
  'tags' => ['node_list:event', 'config:training.settings'],
  'contexts' => ['user.roles', 'url.query_args:category'],
  'max-age' => Cache::PERMANENT,
];
// a node: $node->getCacheTags() returns ['node:5']
Interview one-liner: "Drupal's cache is correct by default: every render array carries tags, contexts and max-age. Cache invalidation is by tag, so editing a node automatically refreshes every page that displayed it."

Lazy builders / placeholders

For personalised or uncacheable parts (cart count, username) use #lazy_builder so the rest of the page stays cached and BigPipe/dynamic page cache fills in the placeholder.

15.3 Performance settings and tuning

  • Configuration → Development → Performance (/admin/config/development/performance): browser and proxy cache max age, aggregate CSS/JS (on in production), clear all caches.
  • Enable Internal Page Cache, Dynamic Page Cache, BigPipe.
  • Use Redis for cache and locks; Varnish or a CDN (Cloudflare, Fastly) for full-page caching with tag-based purging.
  • Optimise images: image styles, WebP, lazy loading, responsive images.
  • Views: avoid loading all entities for huge lists; use fields instead of full entity rendering; add pagers; use caching; avoid heavy relationships.
  • Database: indexes on custom tables, avoid N+1 queries (use loadMultiple), PHP OPcache enabled, current PHP version.
  • Profiling tools: Devel/Webprofiler (dev), Blackfire, New Relic, Xdebug profiler, ddev xdebug.

17.2 JSON:API and REST (headless Drupal)

  • JSON:API (core) automatically exposes all entities: /jsonapi/node/event, /jsonapi/node/event/{uuid}. Supports filter, sort, page[limit], include, fields[node--event]=title,field_location.
  • Enable: ddev drush en jsonapi -y. Config: /admin/config/services/jsonapi (read-only mode recommended unless you need writes).
  • Example: /jsonapi/node/event?filter[field_featured]=1&sort=-created&page[limit]=5&include=field_category
  • RESTful Web Services (core): custom resources and Views "REST export" display.
  • GraphQL (contrib) is an alternative.
  • Authentication: cookie (same domain), Basic Auth (core), OAuth2 / Simple OAuth (contrib), JWT (contrib). Always use HTTPS.
  • CORS: in sites/default/services.yml: cors.config: enabled: true, allowedOrigins: ['https://app.example.com'].
  • Decoupled / headless: Drupal as the back end, a JS front end (Next.js, Nuxt, React). Progressively decoupled: Drupal renders pages and parts use JS components.

  1. Enable language, content_translation, locale (interface translation), config_translation.

19. Interview Q&A

Answer in your own words. The short answers below are interview-length.

A. Basics

1. What is Drupal?

An open-source PHP content management framework on Symfony, used for complex, scalable, secure sites with granular permissions and multilingual support.

2. What is the difference between a node, a content type and a field?

A node is one piece of content. A content type is the template/bundle defining its fields. A field is a data slot.

3. What is an entity? A bundle?

An entity is a data object managed by the Entity API (node, user, term, media...). A bundle is a subtype of an entity type (Article is a bundle of node).

4. What is the difference between content and configuration?

Configuration is site structure/settings exportable as YAML (content types, views, roles). Content is user data (nodes, users, terms) kept in the database, moved by migrations or DB copy.

5. What is the difference between core, contrib and custom?

Core ships with Drupal; contrib is community code on drupal.org; custom is code written for your project.

6. What is a block? A region?

A block is a placeable chunk of output. A region is a theme area where blocks go.

7. What is a view mode?

A named display configuration of an entity (Full, Teaser, Card) so the same content renders differently.

8. What is the difference between a widget and a formatter?

Widget = input on the edit form. Formatter = output on display.

9. What is a taxonomy?

A system of vocabularies containing terms used to categorise content.

10. What is Drupal CMS?

A pre-configured product built on Drupal core using recipes, aimed at easy site building; underneath it is the same Drupal.

11. What is Drupal Core's scaffold and recommended-project?

drupal/recommended-project is the Composer template for new sites; drupal/core-composer-scaffold copies files like index.php into the docroot; drupal/core-recommended locks dependency versions.

12. What is the difference between Drupal 10 and 11?

Drupal 11 requires newer PHP (8.3+), updated Symfony 7, removes deprecated APIs, adds OOP hooks, attributes for plugins, Navigation, recipes and SDC maturing, and Single Directory Components.

13. What is a distribution, install profile, recipe?

Profile: initial setup at install. Distribution: profile plus code for a use case. Recipe: a one-time applicable package of config/modules/content.

14. What does settings.php contain?

Database credentials, hash salt, config sync directory, trusted hosts, file paths, overrides. Environment-specific; not committed with secrets.

15. What is the front controller?

web/index.php, the single entry point that boots Drupal.

B. Site building

16. How do you create a content type and add a field?

Structure → Content types → Add; Manage fields → Add field; configure widget (form display) and formatter (display).

17. How do you show the same content differently in two places?

Create/enable view modes and configure Manage display for each; select the mode in the view or template.

18. What is Views?

A UI query builder for lists, built on displays, fields, filters, sorts, relationships and contextual filters.

19. Contextual filter vs exposed filter?

Contextual filter takes its value from the URL/context. Exposed filter is a form control shown to the visitor.

20. What is a relationship in Views?

A join to a related entity so you can show its fields or filter by them.

21. How do you avoid duplicate rows in a View?

Enable Distinct, use aggregation, or adjust the multi-value field's "Display all values in the same row".

22. How do you add a view to a menu?

Page display → Page settings → Menu → Normal menu entry.

23. How do you display a View in a block?

Add a Block display, then place it in Structure → Block layout.

24. What is the difference between Layout Builder and Paragraphs?

Layout Builder arranges fields/blocks in layouts visually (per content type or per node). Paragraphs lets editors compose content from reusable component types inside a field.

25. Why use Media instead of an Image field?

Media entities are reusable, have metadata (alt, caption), a library UI, and support many sources (video, remote video, documents).

26. How do text formats protect a site?

They run filters (HTML restriction) on user input; weak formats allow XSS, so only trusted roles get Full HTML.

27. How do you create and use roles?

People → Roles; assign permissions on the Permissions page; assign roles to users.

28. What can user 1 do?

Bypasses all permission checks. Use sparingly; use an administrator role for daily work.

29. How do you set up URL aliases?

Manually per node or automatically with Pathauto patterns.

30. How do you enable moderation workflows?

Enable Workflows and Content Moderation; create/edit the Editorial workflow; attach content types; give roles transition permissions.

31. How do you build a contact form?

Core Contact module (/contact) for simple needs or Webform for advanced forms.

32. What are image styles?

Reusable image transformations (scale, crop, convert) that create derivative images on demand.

33. How does Drupal handle multilingual?

Language, Content Translation, Interface Translation and Configuration Translation modules provide languages, translatable fields, translated UI strings and translated config.

34. How do you make a field translatable?

Configuration → Content language and translation → enable for the entity bundle and tick the field.

35. What is a revision?

A stored historical version of an entity; you can compare and revert.

C. Config, deployment, tooling

36. How does configuration management work?

Active config lives in the database; drush cex writes YAML to the sync directory under Git, and drush cim imports it on other environments.

37. What is the deployment order?

composer install → drush updb → drush cim → drush cr (or drush deploy).

38. What is Config Split?

Contrib module that creates environment-specific config sets (dev modules, debug settings).

39. Why does config import complain about UUID?

The site UUID differs; sites must share one UUID to import each other's config.

40. composer.json vs composer.lock?

json = requirements; lock = exact installed versions. Servers use composer install to reproduce.

41. How do you update Drupal core?

Backup; composer update "drupal/core-*" --with-all-dependencies; drush updb; drush cr; test; commit.

42. How do you apply a patch to a contrib module?

Use cweagans/composer-patches, add the patch URL in extra.patches of composer.json, run composer update drupal/module.

43. What is Drush? What is Composer? Difference?

Composer manages PHP packages (installs code). Drush operates on a Drupal site (cache, config, updates).

44. What is DDEV?

A Docker-based local development environment with web server, PHP, database, and tools.

45. How do you migrate a database between environments?

drush sql:dump and drush sql:cli < file, or ddev export-db/import-db, or drush sql:sync @source @self with aliases.

46. What is a Drush alias?

A named remote site definition (@prod) in drush/sites/*.site.yml for running commands remotely.

47. What is the difference between drush cr and drush cc all?

cr rebuilds the registry/container and clears all caches (the right one in modern Drupal); cc all is legacy.

48. How do you do a major upgrade 10 → 11?

Update to the latest 10.x, enable Upgrade Status, fix deprecated code and incompatible modules, update PHP, then require core 11 with Composer, run updb, test.

49. Which files should and should not be in Git?

In: custom code, config, composer files. Out: vendor/, core/contrib (usually), files directory, local settings, secrets.

50. How do you manage secrets?

Environment variables, settings.local.php not in Git, Key module, hosting secret managers.

D. Theming

51. What template engine does Drupal use?

Twig (Symfony); auto-escapes output.

52. How do you override a template?

Enable Twig debug, find the file name suggestion, copy the core template into the theme's templates/, rename for specificity, clear cache.

53. What is a preprocess function?

THEME_preprocess_HOOK(&$variables) that prepares variables for a template.

54. How do you add CSS/JS?

Define a library in THEME.libraries.yml, attach it via info.yml, Twig attach_library(), or #attached.

55. Base theme vs sub-theme vs Starterkit?

Sub-theme inherits from a base theme; Starterkit generates an independent copy.

56. What is SDC?

Single Directory Components: Twig + CSS + JS + metadata schema in one folder, reusable and documented.

57. What are template suggestions?

Alternative file names Drupal tries, from most specific to least, for a render element.

58. What does {{ content|without('field_x') }} do?

Renders remaining content without that field.

59. Why is |raw dangerous?

It disables escaping and enables XSS if the value contains user input.

60. How do you debug Twig?

Set twig.config.debug: true in services.yml, use {{ dump(var) }} or kint, inspect HTML comments.

61. What is the Olivero theme? Claro? Stable9? Starterkit?

Olivero = default front end; Claro = admin; Stable9 = stable markup base; Starterkit = theme generator.

62. What is a render array?

A nested PHP array describing output with # properties (#theme, #type, #markup, #cache, #attached), rendered by the render system.

63. How do you make a theme responsive?

Mobile-first CSS, breakpoints file, responsive image styles, viewport meta (in base templates).

E. Module development

64. What files make a minimum module?

Only MODULE.info.yml, in web/modules/custom/MODULE/.

65. How do you create a custom page?

Routing YAML entry + controller returning a render array.

66. How do you restrict access to a route?

Requirements: _permission, _role, _entity_access, _custom_access.

67. What is a service?

A reusable object defined in services.yml and created by the container.

68. What is dependency injection and why use it?

Passing dependencies via the constructor for testability and loose coupling; avoid \Drupal::service() inside classes.

69. Hooks vs events?

Hooks are named Drupal extension points (OOP attribute #[Hook] in D11); events use Symfony's dispatcher with subscriber classes and priorities.

70. What is a plugin?

A discoverable class implementing one variant of a feature, e.g. blocks, field formatters, queue workers.

71. Annotation vs attribute plugin discovery?

Both identify plugins; attributes (#[Block]) are native PHP 8 and preferred in Drupal 11; annotations still work.

72. How do you create a block programmatically?

A class in src/Plugin/Block extending BlockBase with #[Block] and build().

73. How do you create a form?

Class extending FormBase/ConfigFormBase implementing getFormId, buildForm, validateForm, submitForm, with a route using _form.

74. How do you alter a form?

hook_form_alter or hook_form_FORM_ID_alter.

75. How do you load/save an entity?

Node::load(), Node::create(), $node->save() or the entity type manager storage.

76. Why does entityQuery need accessCheck()?

It must be explicit whether to enforce entity access; omitted causes an exception since Drupal 10.

77. How do you write a database query safely?

Database API with placeholders/conditions, never string concatenation.

78. How do you store module settings?

Config API with defaults in config/install and a schema, edited with a ConfigFormBase form.

79. State vs config vs settings?

Config = exportable site config; state = environment-specific runtime values; settings = server config in settings.php.

80. What is hook_update_N?

One-time database/config update run by drush updb when deploying new code.

81. How do you create a custom entity?

Define the entity class with #[ContentEntityType], interface, base fields, handlers and routes (use drush generate entity:content), then install it via update hook or module install.

82. What is a queue worker used for?

Deferring heavy or slow tasks (emails, API calls) processed by cron or drush queue:run.

83. How do you add a custom field widget or formatter?

Plugin classes in src/Plugin/Field/FieldWidget and FieldFormatter.

84. How do you create a custom Views field/filter?

Plugin classes under src/Plugin/views/field etc. plus hook_views_data for custom tables.

85. How do you log errors?

\Drupal::logger('mod')->error(...) or an injected logger factory.

86. What is a route parameter converter / upcasting?

Converting {node} in a path into a loaded Node object automatically.

87. How do you handle AJAX in forms?

Add #ajax with a callback and wrapper to an element; Drupal replaces the wrapper with the callback's render array.

88. How do you send an email?

Mail manager service + hook_mail().

89. How do you run code on cron?

hook_cron() or a QueueWorker with a cron time.

90. How do you redirect a user after login?

Use the user_login_form alter with a submit handler ($form_state->setRedirect), an event subscriber, or the Login Destination module.

F. Caching, performance, security

91. Explain cache tags, contexts and max-age.

Tags invalidate caches when data changes; contexts create variations by request conditions; max-age limits lifetime.

92. What is BigPipe? Dynamic page cache?

BigPipe streams personalised pieces after cached content; dynamic page cache caches pages for authenticated users with placeholders for dynamic parts.

93. What does max-age 0 do?

Makes the response uncacheable; it bubbles up and can disable page caching, so avoid it.

94. How do you speed up a slow Drupal site?

Enable caches and aggregation, Redis, CDN/Varnish, optimise Views and images, use proper cache metadata, profile with Blackfire/Xdebug, upgrade PHP, add DB indexes, reduce modules.

95. How do you prevent XSS?

Rely on Twig auto-escape, placeholders in t(), restricted text formats, Xss::filter, avoid |raw.

96. How do you prevent SQL injection?

Query builder and placeholders.

97. How do you protect against CSRF?

Form tokens; _csrf_token route requirement for state-changing links.

98. How do you keep a Drupal site secure?

Update promptly, least privilege, HTTPS, trusted hosts, restricted formats, no debug in prod, private files, backups, monitor advisories.

99. What are Drupal security advisories?

SA-CORE-YYYY-NNN and SA-CONTRIB-YYYY-NNN published by the Drupal Security Team with severity and fix versions.

100. What is the flood control?

Core limits repeated login attempts per user/IP and exposes a Flood API for custom features.

G. Scenario questions

101. "A page shows stale content after an edit." What do you check?

Cache tags on the render array, view cache settings, CDN/Varnish purge, custom code with max-age; not just drush cr.

102. "After deployment the site shows config errors."

Check order (updb before cim), UUID mismatch, missing modules in code, drush config:status, logs.

103. "Editors need to approve content before publishing."

Content Moderation + Workflows with an Editorial workflow and role-based transitions.

104. "Show related articles by shared tags."

View with contextual filter "Has taxonomy term ID" using the current node's terms (default value: PHP-free option via Views "Taxonomy terms on node" with "Allow multiple values") and exclude the current node via another contextual filter "Content ID" with "Exclude".

105. "Build a content listing with search, filters and pagination."

Views with exposed filters + pager, or Search API with Facets for large datasets.

106. "Import 10,000 rows from CSV."

Migrate API with migrate_plus, migrate_source_csv, run with drush migrate:import, rollback to retry.

107. "Expose content to a React app."

JSON:API with filters/includes, CORS, Simple OAuth for authentication, caching with tags.

108. "A module update breaks the site."

Restore the backup/snapshot, check release notes and change records, update in a branch, run tests, fix deprecations, or apply a patch.

109. "Restrict a page to premium members."

Add a role and route/permission, or use Group/Content Access; for node-level, node grants.

110. "Different layout for one landing page."

Layout Builder per-node override, or a template suggestion by node ID/alias.

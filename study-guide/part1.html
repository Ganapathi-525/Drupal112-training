1. Drupal basics and architecture

1.1 What is Drupal?

Definition: Drupal is a free, open-source content management framework (CMF) written in PHP, built on Symfony components, using a database (MySQL/MariaDB/PostgreSQL/SQLite), and managed with Composer.

Interview one-liner: "Drupal is an open-source, API-first content management framework on PHP and Symfony. It is strongest for complex content models, multilingual sites, granular permissions and large enterprise or government sites."

1.2 CMS vs CMF vs framework

TermMeaning
CMSSoftware to create and manage content through a UI (WordPress, Drupal).
CMFContent management framework: a CMS whose pieces you can extend and reuse as a framework. Drupal fits here.
FrameworkCode library for building apps (Symfony, Laravel). Drupal uses Symfony underneath.

1.3 Core terminology (know every word)

TermMeaning
CoreThe code that ships with Drupal (web/core). Never edit it.
ContribModules and themes from drupal.org, in web/modules/contrib and web/themes/contrib. Installed with Composer.
CustomYour own code in web/modules/custom and web/themes/custom.
NodeA piece of content (an article, a page).
Content typeA template (bundle) for nodes: Article, Page, Event.
EntityAny data object Drupal manages: node, user, term, file, media, comment, block content, config entity.
BundleA sub-type of an entity type. Node is the entity type, Article is a bundle.
FieldA piece of data on an entity (text, date, image, reference).
WidgetThe input control for a field on the edit form.
FormatterHow a field is displayed on output.
View modeA named way to display an entity (Full, Teaser, Card).
BlockA reusable piece of output placed in a theme region.
RegionAn area defined by a theme (header, sidebar, footer).
ThemeThe presentation layer: Twig templates, CSS, JS.
ModuleCode that adds functionality.
HookA function (or, in Drupal 11, a class method with the #[Hook] attribute) that lets a module alter or react to core behavior.
PluginA swappable piece of functionality discovered automatically (blocks, field types, widgets, formatters, views handlers, queue workers).
ServiceA reusable PHP object managed by the service container (database, logger, current user).
Dependency injection (DI)Passing a class its dependencies through the constructor instead of creating them inside it.
Render arrayA PHP array that describes output; Drupal turns it into HTML.
TwigThe template engine used for themes.
ConfigurationSite settings stored in YAML (content types, views, blocks). Exportable.
ContentUser data stored in the database (nodes, users). Not in config export.
RecipeA reusable package of config, content and module installs applied with drush recipe or php core/scripts/drupal recipe.

1.5 How a Drupal request works (explain this in interviews)

  1. The browser requests /events; the web server sends it to web/index.php.
  2. Drupal boots the kernel (Symfony HttpKernel) and the service container.
  3. Routing matches the path to a route (from a *.routing.yml file or a View).
  4. Access checks decide whether the user may view it.
  5. A controller (or View, or Entity handler) returns a render array.
  6. The render system converts it to HTML using Twig templates and the theme, applying cache metadata.
  7. A Response is returned to the browser.

1.7 Release cycle (interview favourite)

  • Drupal uses semantic versioning: 11.x. A new minor version (11.1, 11.2...) comes about every six months; patch releases fix bugs and security.
  • Major versions (10, 11, 12) remove deprecated code. Move from 10 to 11 by updating to the latest 10.x, fixing deprecations (tool: Upgrade Status module, drupal-check, Rector) and then running composer require drupal/core-recommended:^11 ....
  • Drupal CMS is a product built on Drupal core with recipes and a friendly editor experience. It is not a different codebase.

Exercise 1.1

Task: Open your project folder and identify: where core lives, where you will put a custom module, where uploaded files go, and where config will be exported.
Answer: Core: web/core. Custom module: web/modules/custom/<name>. Uploaded files: web/sites/default/files. Config export: the path in $settings['config_sync_directory'] in settings.php (we will use ../config/sync).

2.3 Installing a fresh Drupal 11 site with DDEV (to explain in interviews)

mkdir mysite && cd mysite
ddev config --project-type=drupal11 --docroot=web
ddev start
ddev composer create-project drupal/recommended-project:^11 .
ddev composer require drush/drush
ddev drush site:install standard --account-name=admin --account-pass=admin -y
ddev drush uli        # one-time login link
ddev launch

2.4 Composer essentials

CommandMeaning / use
ddev composer require drupal/pathautoDownload a contrib module and add it to composer.json
ddev composer require drupal/pathauto:^1.13Specific version constraint
ddev composer remove drupal/pathautoRemove a package (uninstall the module in Drupal first!)
ddev composer update drupal/core-recommended drupal/core-composer-scaffold --with-all-dependenciesUpdate Drupal core
ddev composer update drupal/pathauto --with-dependenciesUpdate one module
ddev composer outdated "drupal/*"List outdated Drupal packages
ddev composer auditCheck for known security advisories
ddev composer installInstall exactly what composer.lock says (used on servers and by teammates)
ddev composer why-not drupal/core 11.5Find out why an upgrade is blocked
Meaning of version signs: ^1.2 = any 1.x at or above 1.2 (not 2.0). ~1.2.3 = 1.2.x at or above 1.2.3. * = any. dev-main = branch.
composer.json vs composer.lock: composer.json lists what you asked for; composer.lock records the exact versions installed. Commit both. On deployment run composer install (reads the lock), not update.
Never download modules by hand into web/modules and never edit core or contrib. Use Composer, and for fixes use patches (cweagans/composer-patches).
